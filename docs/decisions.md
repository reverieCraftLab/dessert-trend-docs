# 결정 기록

항목마다 "정한 것 / 이유 / 다른 선택지"를 남깁니다. 나중에 왜 그렇게 했는지 설명할 수 있게 하는 것이 목적입니다.

## D-01. 구현 전에 요구사항 기술서부터 작성한다 (2026-10-17)

- **정한 것**: 코드나 테이블을 만들기 전에 요구사항 기술서를 먼저 쓴다.
- **이유**: 이전에는 요구사항 없이 무작정 만들었고, 그 결과 왜 그렇게 만들었는지 설명하기 어려웠다. 요구사항이 있어야 이후 DB 설계와 API 설계의 근거가 생긴다.
- **다른 선택지**: 바로 구현하면서 필요한 기능을 그때그때 추가하기.

## D-02. 문서는 GitHub 저장소에 마크다운으로 작성한다 (2026-10-17)

- **정한 것**: 문서를 GitHub 저장소의 `docs/` 폴더에 마크다운 파일로 둔다.
- **이유**: 포트폴리오에서 링크 하나로 바로 열려 보이고, 커밋 기록에 요구사항이 바뀐 과정이 남는다.
- **다른 선택지**: Notion(초안 작성은 편하지만 변경 이력이 약함), 블로그(완성된 글을 공개하기엔 좋지만 정리 단계에는 이르다), 엑셀 파일(GitHub에서 바로 열리지 않음).

## D-03. 문서 전용 저장소 `dessert-trend-docs`로 시작한다 (2026-10-17)

- **정한 것**: 지금은 문서만 담는 별도 저장소를 만들어 시작한다.
- **이유**: 아직 코드가 없는 단계라 기획 문서만 깔끔하게 보이게 하려는 목적이다.
- **다른 선택지**: 기존 갤러리 저장소의 `docs/` 폴더에 쓰기(문서와 갤러리 코드가 섞임).
- **남은 과제**: 구현이 시작되면 문서를 코드 저장소의 `docs/`로 옮기거나, README에서 코드 저장소로 링크를 걸어 연결한다.

## 미확정

- **요구사항 목록 형식**: 마크다운 표를 기본으로 하고, 표가 길어지면 `.csv`를 보조로 쓰는 안. 엑셀(`.xlsx`)을 쓸지는 아직 정하지 않았다. 확정되면 결정 기록으로 올린다.
