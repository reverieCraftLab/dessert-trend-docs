# 결정 기록

실제 사이트를 만드는 결정만 기록합니다. 항목마다 "정한 것 / 이유 / 다른 선택지"를 남겨서, 나중에 왜 그렇게 했는지 설명할 수 있게 하는 것이 목적입니다.

## D-01. 주 타깃은 일반 유저, 소상공인은 서브로 한다 (2026-10-17)

- **정한 것**: 주 타깃을 일반 유저로, 소상공인을 서브 타깃으로 한다.
- **이유**: 이 프로젝트의 핵심이 핀터레스트 스타일로 디저트를 둘러보고 가게를 찾는 경험이라서, 일반 유저 중심이 프로젝트에 맞다고 판단했다.
- **다른 선택지**: 소상공인을 주 타깃으로 하는 유행 시점 판단 서비스. 처음에 고려했던 방향이다.

## D-02. 유행 지표 화면은 MVP에서 제외하고, 행동 기록은 처음부터 한다 (2026-10-17)

- **정한 것**: 소상공인용 유행 지표 화면은 나중에 추가한다. 대신 사용자의 특정 행동은 초기부터 기록한다.
- **이유**: 지표는 사용자 행동 데이터로 만들 계획인데, 사용자가 모이기 전에는 그 데이터가 유효하지 않다. 다만 지표를 나중에 붙이려면 그때까지 쌓인 데이터가 필요하므로, 화면은 미뤄도 기록은 미룰 수 없다.
- **다른 선택지**: 처음부터 지표 화면을 만들기.
- **남은 과제**: 어떤 행동을 기록할지 정한다.

## D-03. 초기 데이터는 외부 API(네이버)로 가져온다 (2026-10-17)

- **정한 것**: 초기 데이터는 외부 API로 가져오고, 네이버 API를 최종 후보로 한다. 대상은 NAVER 검색(이미지, 블로그, 지역, 뉴스, 카페)과 Data Lab(검색어트렌드, 쇼핑인사이트)이다.
- **이유**: 무료 요청 횟수가 많다고 판단했고, 한국에서는 맛집과 위치를 찾을 때 네이버 지도를, 후기를 볼 때 네이버 블로그를 많이 쓰므로 네이버가 가장 효율이 좋다고 보았다.
- **다른 선택지**: 카카오 등 다른 API. 비교는 아직 하지 않았다.
- **확인한 것**: 네이버 API 허브 콘솔 화면 기준 NAVER 검색은 일 25,000회·월 775,000회, Data Lab은 API별 월 50,000회로 표시된다.
- **확인한 것(제공 기능)**: 네이버 API 허브 상품 소개 페이지 기준으로, 이미지 검색은 썸네일 구성 등에 쓰는 이미지 검색 결과를, 지역 검색은 네이버 지역 서비스에 등록된 업체·기관 검색 결과를 제공한다. 검색어 트렌드와 쇼핑 인사이트는 조회 기간 내 최고 시점을 100으로 두고 나머지를 환산한 상대 지표로 제공한다. 이 페이지에는 이미지 이용 약관이 나와 있지 않다.
- **남은 과제**: 이용 약관(특히 이미지 사용 범위)을 공식 문서로 확인한다. 검색 API 5종이 같은 호출 한도를 공유하는지 확인한다. 각 API를 어떤 용도로 쓸지 정한다.
